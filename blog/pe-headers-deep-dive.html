PE Format: Deep Dive into Optional Headers & Data Directories

Author: Musaed
Published: March 1, 2026
Topic: Windows Internals / PE Structure

Introduction

The Portable Executable (PE) format is the standard executable file structure utilized by modern 32-bit and 64-bit Windows operating systems. While the legacy DOS header and COFF File Header establish basic file validation, the IMAGE_OPTIONAL_HEADER structure contains the vital parameters required by the Windows OS loader (ntdll!LdrpInitializeProcess) to map image sections into virtual memory.

The IMAGE_OPTIONAL_HEADER64 Structure

Despite its name, the Optional Header is mandatory for executable files and dynamic-link libraries. In 64-bit binaries (PE32+), key 32-bit fields such as ImageBase, SizeOfStackReserve, and SizeOfHeapReserve are expanded to 64-bit integers (ULONGLONG).

C / WinNT.h IMAGE_OPTIONAL_HEADER64 Definition 
typedef struct _IMAGE_OPTIONAL_HEADER64 {
    WORD        Magic;                       // 0x020b for PE32+ (x64)
    BYTE        MajorLinkerVersion;
    BYTE        MinorLinkerVersion;
    DWORD       SizeOfCode;
    DWORD       SizeOfInitializedData;
    DWORD       SizeOfUninitializedData;
    DWORD       AddressOfEntryPoint;        // RVA of entry point
    DWORD       BaseOfCode;                 // RVA of code section
    ULONGLONG   ImageBase;                  // Preferred load address (e.g. 0x140000000)
    DWORD       SectionAlignment;           // In-memory page alignment (typically 0x1000)
    DWORD       FileAlignment;              // On-disk file alignment (typically 0x200)
    WORD        MajorOperatingSystemVersion;
    // ... Subsystem & DLL Characteristics ...
    DWORD       NumberOfRvaAndSizes;        // Number of DataDirectory entries (16)
    IMAGE_DATA_DIRECTORY DataDirectory[16];
} IMAGE_OPTIONAL_HEADER64, *PIMAGE_OPTIONAL_HEADER64;

Section vs File Alignment

One of the fundamental differences when parsing PE files statically versus reading mapped memory is the alignment discrepancy:

  • FileAlignment: Dictates the granularity of section boundaries on disk (commonly 512 bytes / 0x200).
  • SectionAlignment: Dictates the page granularity of section boundaries when mapped into the process virtual address space (commonly 4096 bytes / 0x1000).

Because of this difference, a Relative Virtual Address (RVA) does not map 1:1 to a raw file offset. To calculate the raw offset for an address located in a given section:

C++ RVA to File Offset Conversion 
DWORD RvaToRawOffset(DWORD dwRva, PIMAGE_NT_HEADERS pNtHeaders) {
    PIMAGE_SECTION_HEADER pSection = IMAGE_FIRST_SECTION(pNtHeaders);
    for (WORD i = 0; i < pNtHeaders->FileHeader.NumberOfSections; ++i, ++pSection) {
        if (dwRva >= pSection->VirtualAddress && 
            dwRva < (pSection->VirtualAddress + pSection->Misc.VirtualSize)) {
            return (dwRva - pSection->VirtualAddress) + pSection->PointerToRawData;
        }
    }
    return 0; // Not found in mapped sections
}

Key Data Directories

The array of 16 IMAGE_DATA_DIRECTORY elements at the tail of the Optional Header points to primary subsystem tables:

Index Directory Constant Description
0 IMAGE_DIRECTORY_ENTRY_EXPORT Export Directory Table (functions exported by DLLs).
1 IMAGE_DIRECTORY_ENTRY_IMPORT Import Directory Table (imported external APIs).
2 IMAGE_DIRECTORY_ENTRY_RESOURCE Resource Directory Table (icons, dialogs, version info).
3 IMAGE_DIRECTORY_ENTRY_EXCEPTION Exception Directory (.pdata table for x64 SEH unwinding).
4 IMAGE_DIRECTORY_ENTRY_SECURITY Security Directory (Authenticode signatures, PKCS #7).
5 IMAGE_DIRECTORY_ENTRY_BASERELOC Base Relocation Table (fixups required if ASLR reallocates image base).

Conclusion

Mastering the PE Optional Header layout is foundational for low-level reverse engineering, writing custom loaders, unpacking obfuscated binaries, and conducting binary analysis.
