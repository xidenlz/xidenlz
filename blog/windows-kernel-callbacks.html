Understanding Windows Kernel Process & Thread Callbacks

Author: Musaed
Published: February 18, 2026
Topic: Windows Kernel / Driver Security

Overview

In modern 64-bit Windows environments, Kernel Patch Protection (PatchGuard) prevents security drivers and software from modifying the System Service Descriptor Table (SSDT) or performing inline hooks on kernel code. To provide legitimate security software, EDRs, and anti-cheat drivers with visibility and control over process execution, Microsoft introduced official notification routines and Object Manager callbacks.

Process Creation Notifications

Drivers register for process creation events using PsSetCreateProcessNotifyRoutineEx. The callback receives a pointer to a PS_CREATE_NOTIFY_INFO structure containing:

  • Parent Process ID and Creator Thread ID.
  • The fully qualified image file path of the executable.
  • The complete command line string.
  • A status output field (CreationStatus) allowing the driver to block process startup with STATUS_ACCESS_DENIED.
C Process Creation Callback Handler 
VOID ProcessNotifyCallbackEx(
    PEPROCESS Process,
    HANDLE ProcessId,
    PPS_CREATE_NOTIFY_INFO CreateInfo
) {
    if (CreateInfo != NULL) {
        // Process is starting up
        KdPrint(("[+] New Process Spawned: PID %llu | Path: %wZ\n", 
            (ULONG_PTR)ProcessId, CreateInfo->ImageFileName));
            
        // Inspect or enforce policy
        if (IsBlockedBinary(CreateInfo->ImageFileName)) {
            CreateInfo->CreationStatus = STATUS_ACCESS_DENIED;
        }
    } else {
        // Process is terminating
        KdPrint(("[-] Process Terminated: PID %llu\n", (ULONG_PTR)ProcessId));
    }
}

Object Manager Callbacks: ObRegisterCallbacks

While notification routines inform the driver after an event occurs, ObRegisterCallbacks provides pre-operation and post-operation interception of handle creation for *PsProcessType and *PsThreadType.

Inside the pre-operation callback, the driver can inspect OperationInformation->Parameters->CreateHandleInformation.DesiredAccess and strip sensitive access rights before the Object Manager returns the handle to the caller.

C Pre-Operation Handle Access Filtering 
OB_PREOP_CALLBACK_STATUS HandlePreCallback(
    PVOID RegistrationContext,
    POB_PRE_OPERATION_INFORMATION OpInfo
) {
    if (OpInfo->ObjectType == *PsProcessType) {
        PEPROCESS TargetProcess = (PEPROCESS)OpInfo->Object;
        
        if (IsProtectedProcess(TargetProcess)) {
            // Strip write, read, and thread injection permissions
            ACCESS_MASK MaskToStrip = PROCESS_VM_READ | 
                                      PROCESS_VM_WRITE | 
                                      PROCESS_VM_OPERATION | 
                                      PROCESS_CREATE_THREAD | 
                                      PROCESS_DUP_HANDLE;
                                      
            OpInfo->Parameters->CreateHandleInformation.DesiredAccess &= ~MaskToStrip;
        }
    }
    return OB_PREOP_SUCCESS;
}

Security Implications

Object manager filtering makes user-mode API hooking and debugging against protected applications ineffective through standard user-mode debugging interfaces. Security researchers investigating protected environments must examine how drivers validate handle origins, whether handle duplication can be leveraged, or how kernel-mode communications are authenticated.
